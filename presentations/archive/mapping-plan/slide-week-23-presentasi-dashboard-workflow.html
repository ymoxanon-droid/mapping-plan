02
Masalah

Deck Hardcoded & Tidak Skalabel

Tiap deck baru = edit array JS, push, deploy. Dalam seminggu ada 3+ task berbeda — workflow ini gak tahan skala.

Empat Pain Point Utama

Apa yang Bikin Workflow Macet

Array DECKS Hardcoded

Tambah deck = edit JS di public/presentasi/index.html, commit, push, deploy. Tiap kali.

Tidak Ada Admin UI

Tidak ada form CRUD — semua manipulasi data lewat editor kode.

File HTML Tanpa Storage

Tidak ada tempat penyimpanan terstruktur — deck nyangkut di folder lokal & repo terpisah.

Tidak Relasi ke Job/Task

Project list manual, status enum hardcoded, listing tidak bisa di-group otomatis per meeting.

Kalau dibiarkan: tiap minggu butuh sentuh kode untuk publikasi rekap — workflow yang hostile untuk operator non-developer.
Tujuan Proyek

Goal & Constraint

Goals

  • Data-driven dari Database, bukan array statis
  • Upload deck via UI admin (tanpa edit kode)
  • Auto-group per meeting Selasa, ISO week label
  • Sync dengan jobs/tasks existing

Constraints

  • Tetap pakai Supabase Free + Vercel Free
  • Stack existing: React + Vite + Supabase
  • Tidak boleh nambah service eksternal berbayar
  • Backward compatible dengan schema jobs/tasks
Solusi harus murah, ringan, dan plug-in ke arsitektur yang sudah berjalan.

Tantangan #1

Hardcoded vs DB-Driven

Sebelum

  • Edit array DECKS di JS untuk tiap deck baru
  • Commit → push → deploy untuk publikasi rekap
  • Tidak bisa di-handle non-developer
  • Skala 3+ deck/minggu = bottleneck

Sesudah

  • Form upload di /admin
  • Auto muncul di /presentations
  • Tidak butuh sentuh kode
  • Source of truth: DB, bukan repo
Data-driven UI selalu lebih sustainable daripada hardcoded list — biaya migrasi sekali, benefit selamanya.
Tantangan #2

Content-Type & CSP dari Supabase Storage

Sebelum

  • File .html dari public URL tampil sebagai source code mentah
  • Content-Type: text/plain dipakai default
  • Script Reveal.js diblokir CSP sandbox
  • Slide jadi teks panjang, tidak interaktif

Sesudah

  • Vercel Edge fetch + re-serve text/html
  • Tidak set CSP sandbox
  • Reveal.js render proper, panah & space jalan
  • 1 file edge function, 0 dependency tambahan
Supabase Storage didesain untuk asset statis (PDF/image), bukan HTML interaktif → butuh proxy layer.

Pembelajaran

Insight Teknis & Operasional

Storage ≠ Web Host

Supabase Storage punya batasan untuk HTML interaktif. Proxy layer di edge function adalah pattern reliable untuk overcome Content-Type & CSP.

Data-Driven Menang

Hardcoded list selalu menumpuk technical debt. Investasi 1x untuk schema + UI lebih murah dari maintenance jangka panjang.

Auto-Fill Cegah Drift

Auto-mapping task status → presentation status hemat klik & cegah inkonsistensi data entry antar tabel.

Tiga insight ini reusable untuk subsistem lain (notifikasi, comments, versioning deck) di iterasi berikutnya.
