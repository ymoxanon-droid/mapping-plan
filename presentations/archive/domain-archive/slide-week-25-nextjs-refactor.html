02
Masalah

Aman di Permukaan, Debt di Dalam

App jalan normal — tapi beberapa hal penting diam-diam menumpuk karena Vite tak pernah mengecek.

Pain Point

4 Masalah Inti

🏝️ Pulau sendiri

Tim pakai Next, app ini Vite — beda stack, susah maintain & onboarding bareng.

🔍 Tak ada type-check

Vite (esbuild) buang tipe TANPA mengeceknya → error tipe tak pernah ketahuan saat build.

🚦 Tak ada lint-gate

ESLint cuma manual & jarang dijalankan — warning numpuk diam-diam.

📦 Hidden debt

76 type-error + 72 lint-warning sudah ada dari dulu — cuma ketutup karena tak ada yang mengecek.

Analogi: "aman" di Vite = lampu indikator dasbor dicopot, bukan mesinnya lebih sehat.
Tujuan Proyek

Goal & Constraint

🎯 Goals

  • Pindah ke Next.js (App Router)
  • Nyalakan type-safety penuh saat build
  • ESLint bersih → 0 warning
  • Pasang gate anti-regresi (pre-push)

⚠️ Constraints

  • Backend Supabase (25 edge fn + DB) HARAM tersentuh
  • Hot-path god-file NamecheapPage (~5.500 baris) dijaga
  • RDP blokir outbound TCP → deploy via proxy
  • Keep-alive (cold-load 13 dtk) tak boleh hilang

04
Implementasi

Eksekusi: Migrasi + Hardening

Dua fase — pindahkan dulu agar jalan di Next, lalu beresin kualitas yang selama ini ketutup.

Eksekusi

2 Fase Pengerjaan

Fase 1 · Migrasi inti

  • Catch-all shell ssr:false (keep-alive utuh)
  • Env: import.meta.env → process.env.NEXT_PUBLIC_
  • src/pages → src/screens (Next reserve "pages/")
  • Helper assetUrl (normalisasi import gambar)

Fase 2 · Hardening

  • Buang ignoreBuildErrors → type-check penuh (76→0)
  • ESLint 72→0 bertahap (S1–S6, tiap tahap di-tag)
  • Gate pub: typecheck + lint sebelum push
Migrasi = sehari kerja; tapi menyalakan "rem" (type + lint) yang Vite tak punya = nilai jangka panjang.
Tantangan #1

Keep-alive Routing

❌ Masalah

  • App Router Next unmount halaman tiap navigasi
  • NamecheapPage cold-load 13 dtk tiap balik ke /domains
  • Fitur keep-alive (nahan halaman tetap hidup) hilang

✓ Solusi

  • Catch-all [[...slug]] + ssr:false
  • react-router di dalam → Next tak unmount apa pun
  • Cold-load 13 dtk dibayar sekali per sesi
Trade-off keep-alive vs idiom Next murni — dipilih catch-all biar UX cold-load 13 dtk tak kembali.
Tantangan #2

76 Error, Ternyata 1 Akar

❌ Gejala

  • Buang ignoreBuildErrors → 76 error Supabase muncul
  • Terlihat seperti bug library supabase-js v2.103
  • Regen database.types.ts tak menolong

✓ Akar & fix

  • process.env.* = string | undefined
  • Arg createClient error → TS drop inferensi generic → schema jatuh ke "public"
  • Fix 3 baris ?? "" → 76 → 0
Jangan langsung menyalahkan library — 76 error ternyata satu akar sepele (env var bertipe longgar).

Value

Apa yang Berubah

Sebelum (Vite)

  • Stack beda dari tim — "pulau sendiri"
  • Tak ada rem (type / lint) saat build
  • Debt ketutup, god-file makin gemuk

Sesudah (Next.js)

  • Satu stack dengan tim — maintain bareng
  • "Rem otomatis" nyala: type + lint gate tiap push
  • Kode bersih & ter-gate → pondasi fitur baru lebih cepat
Buat user: app sama persis. Buat tim: lebih mudah, lebih aman, & lebih cepat mengembangkan fitur.
Pembelajaran

Insight Teknis & Operasional

🚗 Aman ≠ Sehat

"Aman" di Vite karena lampu indikator dicopot. Nyalakan type + lint = lihat PR lama yang selama ini ketutup.

🔬 Cek akar dulu

76 type-error ternyata 1 akar (env var string|undefined bikin TS drop inferensi) — jangan buru-buru menyalahkan library.

🛡️ Audit adversarial

Untuk yakin god-file tak rusak: 5 agen + 1 skeptic, pakai tsc/diff/grep — bukan sekadar "percaya".

Migrasi yang baik = nol regresi + dapat "rem otomatis" sebagai bonus untuk masa depan.
