02
Masalah

Konteks yang Terpecah

Tool & layanan yang terpisah membuat kerja lambat, rawan salah, dan sulit diaudit.

Akar Masalah

4 Titik Nyeri Utama

🔁 Login & buka berulang

Tiap layanan punya akun, alamat, dan tampilan sendiri — waktu habis untuk berpindah-pindah.

🧩 Data tidak nyambung

Data domain di registrar, DNS, dan SEO tidak terhubung; disatukan manual lewat copy-paste.

🕵️ Audit tidak terpusat

Sulit menjawab "siapa mengubah apa, kapan" karena jejak tersebar di banyak tempat.

🔑 Integrasi provider rawan

API key tiap layanan tersebar — berisiko bocor bila dipanggil langsung dari sisi browser.

Dibiarkan: kerja makin lambat dan risiko salah/keamanan naik seiring portfolio bertambah.
Tujuan Proyek

Goal & Constraint

🎯 Goals

  • Satu platform untuk semua modul (satu pintu)
  • Satu login untuk seluruh fitur (SSO)
  • Integrasi provider yang aman & terpusat
  • Audit aktivitas tercatat di satu tempat

⚠️ Constraints

  • API key tidak boleh sampai ke browser
  • Ikut stack existing: React + Supabase
  • Integrasi bertahap, tanpa mengganggu yang jalan
  • Tetap ringan walau modul terus bertambah
Sasarannya jelas: satu pintu yang aman & terpusat, dibangun bertahap di atas yang sudah ada.

04
Implementasi

Eksekusi Integrasi

Tiga lapis: konsolidasi modul, integrasi provider, dan penyatuan akses.

Lapis 1 · Modul

Konsolidasi 16 Modul jadi 1 App

Routing + Keep-Alive

  • Tiap fitur = satu rute (/domains, /disavow, …)
  • Halaman lazy-load saat pertama dibuka
  • Setelah dibuka, modul tetap "hidup" → pindah instan

Sidebar 5 Grup

  • Utama · Statistics · Data & Keyword
  • Tools · Admin
  • Semua modul tampil dalam satu navigasi
Dari banyak dashboard terpisah → satu navigasi; pengguna tak perlu "buka sana-sini".
Lapis 2 · Provider

7 Provider lewat 18 Edge Function

Registrar
Namecheap · Dynadot
sync domain, perpanjang, nameserver
DNS / Hosting
Cloudflare · Vercel
add zone, attach domain, redirect
SEO / Metrik
Ahrefs · DataForSEO
authority, backlink, SERP/keyword
Search
Search Console
OAuth + daftar properti (GSC)
API key disimpan sebagai secret di server (Edge Function) — tidak pernah dikirim ke browser.
Lapis 3 · Akses

Satu Login untuk Semua Modul

SSO + Admin Roles

  • Login via Google OAuth atau akun admin
  • Peran (role) menentukan akses modul tertentu
  • Kelola user terpusat (create / update / delete)

Proteksi

  • AuthGate: aplikasi terkunci sebelum login
  • Login lockout setelah percobaan gagal
  • Anti-snoop (blok devtools) di produksi
Satu gerbang masuk: keamanan & hak akses diatur di satu tempat, bukan di tiap tool.
Jaring Pengaman

Audit & Sinkronisasi

🧾 Audit terpusat

Setiap aksi penting (login, perpanjang domain, perubahan) tercatat di activity_log & admin_audit_log — bisa ditelusuri per sesi.

⚡ Realtime sync

Perubahan data langsung tampil di UI lewat postgres_changes, dengan debounce agar tabel tidak berkedip saat operasi massal.

Karena terpadu, jejak audit & data terkini ada di satu sumber kebenaran.
Tantangan

API Key Tidak Boleh Bocor

❌ Kalau dipanggil dari browser

  • API key provider terekspos di sisi klien
  • Kuota/biaya bisa disalahgunakan pihak lain
  • Tiap tool kelola key sendiri-sendiri

✓ Lewat Edge Function

  • Semua panggilan provider berjalan di server
  • Key disimpan sebagai secret, tak pernah ke browser
  • Satu tempat kelola kredensial & biaya
Pelajaran: integrasi provider wajib server-side — keamanan jadi syarat, bukan opsi.

Dampak untuk Pengguna

Sebelum vs Sesudah

❌ Sebelum

  • Buka 5–7 tool berbeda, login berulang
  • Pindah data antar tool dengan copy-paste
  • Jejak perubahan tersebar, sulit ditelusuri
  • Kredensial provider tercecer

✓ Sesudah

  • 1 platform, 1 login, semua modul di sidebar
  • Data tersinkron otomatis (realtime)
  • Audit terpusat: "siapa, apa, kapan" jelas
  • API key aman di server, terkelola satu tempat
Untuk tim: kerja lebih cepat, lebih sedikit salah, dan lebih mudah dipertanggungjawabkan.
Pembelajaran

Insight Teknis & Operasional

🔑 Provider = server-side

Edge Function bukan sekadar gaya — ia melindungi API key & memusatkan biaya.

🧩 Modular monolith cukup

Untuk skala ini, satu app modular lebih sederhana & murah daripada micro-frontend.

🧾 Audit sejak awal

Mencatat aktivitas dari hari pertama bikin telusur masalah jauh lebih mudah.

Integrasi yang baik bukan cuma "nyambung", tapi aman, terpusat, dan bisa diaudit.
