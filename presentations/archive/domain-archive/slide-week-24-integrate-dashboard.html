Alur 4 · Kolaborasi

Inbox & Approval

Banyak pengguna bekerja di satu dashboard; permintaan berisiko (perpanjangan, catatan, hapus massal) melewati inbox & persetujuan admin, lalu terekam di activity_log + admin_audit_log. Status: read / resolved / dismissed.

Inilah sisi "collaboration": kerja bersama dengan kontrol persetujuan & jejak audit.
Alur 5 · Data

Sinkronisasi Realtime

Perubahan data
insert/update/delete
→
Supabase Realtime
postgres_changes
→
Refetch (debounced)
get_domains_page()
→
UI update
tabel ter-refresh
⚙
Pagination di sisi server
get_domains_page() → tabel tetap ringan walau data besar.
≈
Refetch di-debounce
Banyak event beruntun tidak bikin tabel berkedip (anti-flicker).
◐
Mode "silent" saat operasi massal
Loading tidak muncul tiap event.
Perubahan langsung terlihat, tapi tetap mulus & hemat — bukan refresh manual.
