02
Masalah

Konteks yang Terpecah

Tool & layanan terpisah membuat kerja lambat, rawan salah, dan sulit diaudit.

Akar Masalah

4 Titik Nyeri Utama

🔁 Login & buka berulang

Tiap layanan punya akun, alamat, dan tampilan sendiri — waktu habis berpindah-pindah.

🧩 Data tidak nyambung

Data registrar, DNS, dan SEO tidak terhubung; disatukan manual lewat copy-paste.

🕵️ Audit tidak terpusat

Sulit menjawab "siapa mengubah apa, kapan" karena jejak tersebar.

🔑 Integrasi provider rawan

API key tersebar — berisiko bocor bila dipanggil dari sisi browser.

Dibiarkan: kerja makin lambat dan risiko salah/keamanan naik seiring portfolio bertambah.
Tujuan Proyek

Goal & Constraint

🎯 Goals

  • Satu platform untuk semua modul
  • Satu login (SSO) untuk seluruh fitur
  • Integrasi provider yang aman & terpusat
  • Audit aktivitas di satu tempat

⚠️ Constraints

  • API key tidak boleh ke browser
  • Ikut stack existing: React + Supabase
  • Bertahap, tanpa ganggu yang jalan
  • Tetap ringan walau modul bertambah
Sasaran jelas: satu pintu yang aman & terpusat, dibangun bertahap di atas yang sudah ada.

Tantangan

API Key Tidak Boleh Bocor

  • API key provider terekspos di klien

  • Tiap tool kelola key sendiri

  • Key jadi secret, tak pernah ke browser
  • Satu tempat kelola kredensial & biaya

Dampak untuk Pengguna

Sebelum vs Sesudah

❌ Sebelum

  • Buka 5–7 tool, login berulang
  • Pindah data antar tool (copy-paste)
  • Jejak perubahan tersebar
  • Kredensial provider tercecer

✓ Sesudah

  • 1 platform, 1 login, semua modul di sidebar
  • Data tersinkron otomatis (realtime)
  • Audit terpusat: "siapa, apa, kapan"
  • API key aman di server
Untuk tim: kerja lebih cepat, lebih sedikit salah, lebih mudah dipertanggungjawabkan.
Pembelajaran

Insight Teknis & Operasional

🔑 Provider = server-side

Edge Function bukan sekadar gaya — ia melindungi API key & memusatkan biaya.

🧩 Modular monolith cukup

Untuk skala ini, satu app modular lebih sederhana & murah dari micro-frontend.

🧾 Audit sejak awal

Mencatat aktivitas dari hari pertama bikin telusur masalah jauh lebih mudah.

Integrasi yang baik bukan cuma "nyambung", tapi aman, terpusat, dan bisa diaudit.
